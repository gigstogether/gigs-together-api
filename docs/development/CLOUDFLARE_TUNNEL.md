# Local HTTPS access with Cloudflare Tunnel

This tunnel provides public HTTPS access to the locally running API and frontend, including Telegram bot webhook handling and Mini App development.

The development setup uses one locally managed tunnel named `gigs` for both repositories:

| Public URL                        | Local service           | Repository            |
| --------------------------------- | ----------------------- | --------------------- |
| `https://apidev.gigstogether.com` | `http://localhost:3000` | `gigs-together-api`   |
| `https://dev.gigstogether.com`    | `http://localhost:3001` | `gigs-together-front` |

## Start an already configured tunnel

In a separate terminal, run:

```text
cloudflared tunnel run gigs
```

Keep the tunnel terminal open. Stop the tunnel with `Ctrl+C`.

## Installation and local files

### Windows

Install `cloudflared` using the Windows installer from the [official downloads](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/#windows).
The installation found on the Windows development machine is `C:\Program Files (x86)\cloudflared\cloudflared.exe`.
Add its installation directory to `PATH`. Alternatively, invoke it by its full path in PowerShell:

```powershell
& 'C:\Program Files (x86)\cloudflared\cloudflared.exe' tunnel run gigs
```

### macOS

Install with Homebrew:

```bash
brew install cloudflared
```

Alternatively, use the macOS binary from the [official downloads](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/#macos).

### Shared commands and file locations

With `cloudflared` on `PATH`, the remaining CLI commands are the same on both platforms. Check the installation with:

```text
cloudflared --version
```

Local tunnel files live in `%USERPROFILE%\.cloudflared` on Windows and `~/.cloudflared` on macOS:

- `config.yml`: manually maintained routing configuration.
- `<tunnel-uuid>.json`: tunnel credentials generated by `cloudflared tunnel create`.
- `cert.pem`: account certificate generated by `cloudflared tunnel login`.

Keep credentials and the certificate outside both repositories.

## Update cloudflared

To update a standalone installation, run:

```text
cloudflared update
```

For a Homebrew installation, run `brew upgrade cloudflared` instead. Restart the tunnel after updating.

## Initial tunnel setup

Use the Cloudflare account managing `gigstogether.com`. When reusing an existing tunnel and DNS routes, skip the creation and DNS commands below.

```text
cloudflared tunnel login
cloudflared tunnel list
```

`gigs` is the tunnel name stored in Cloudflare alongside its UUID, not a shell alias.
For a new setup only, create it with:

```text
cloudflared tunnel create gigs
```

This generates the credentials JSON; it does not generate `config.yml`.
Use the UUID shown by `cloudflared tunnel list` or returned when creating the tunnel.

## Manually edit config.yml

Manually create or edit `config.yml` in a text editor at the path for your platform:

| Platform | Configuration file                      |
| -------- | --------------------------------------- |
| Windows  | `%USERPROFILE%\.cloudflared\config.yml` |
| macOS    | `~/.cloudflared/config.yml`             |

In the example below, replace `<absolute-path-to-credentials-json>` with the actual absolute path to the credentials file:

- Windows: `C:/Users/<windows-user>/.cloudflared/<tunnel-uuid>.json`. Use forward slashes to avoid Windows path escaping.
- macOS: `/Users/<macos-user>/.cloudflared/<tunnel-uuid>.json`.

Replace `<tunnel-uuid>` in `tunnel` and the credentials filename with your tunnel's UUID.

```yaml
tunnel: <tunnel-uuid>
credentials-file: '<absolute-path-to-credentials-json>'

ingress:
  - hostname: apidev.gigstogether.com
    service: http://localhost:3000
  - hostname: dev.gigstogether.com
    service: http://localhost:3001
  - service: http_status:404
```

The final rule returns `404` for unmatched hostnames. Check routing configuration with:

```text
cloudflared tunnel ingress validate
```

For a new setup only, create the two DNS routes:

```text
cloudflared tunnel route dns gigs apidev.gigstogether.com
cloudflared tunnel route dns gigs dev.gigstogether.com
```

If the config is stored elsewhere, specify it explicitly when starting the tunnel, replacing the placeholder with its absolute path on your platform:

```text
cloudflared tunnel --config "<absolute-path-to-config.yml>" run gigs
```

## Application configuration

In the backend `.env.dev`, set these tunnel-related values alongside the other required configuration:

```env
PORT=3000
APP_BASE_URL=https://dev.gigstogether.com
CORS_ORIGINS=https://dev.gigstogether.com
```

`CORS_ORIGINS` above allows credentialed requests from the tunnel frontend.
If other browser origins are needed, add their full origins to the comma-separated allowlist.

In the frontend `.env.local`, set:

```env
NEXT_PUBLIC_APP_API_BASE_URL=https://apidev.gigstogether.com
NEXT_PUBLIC_APP_BASE_URL=https://dev.gigstogether.com
ALLOWED_DEV_ORIGINS=dev.gigstogether.com
```

`ALLOWED_DEV_ORIGINS` takes hostnames without a protocol or port. Restart the affected application after changing environment configuration.

For Telegram development, use the frontend origin `https://dev.gigstogether.com` in the [Required Telegram setup](../../README.md#required-telegram-setup): the suggestion Mini App URL is `https://dev.gigstogether.com/suggest/launch`, the admin Mini App URL is `https://dev.gigstogether.com/admin/telegram`, and Web Login must allow that frontend origin.
The development bot webhook URL is `https://apidev.gigstogether.com/v1/telegram/updates`; follow the existing webhook secret requirements in that section.

## Checks and troubleshooting

- Check `http://localhost:3000/health` first, then `https://apidev.gigstogether.com/health`.
- Open `http://localhost:3001` first, then `https://dev.gigstogether.com`.
- If local access fails, check the application terminal and its port. The frontend must run on `3001` for these ingress rules, even though Next.js defaults to `3000`.
- If local access works but the public URL fails, check the tunnel terminal, config path, hostname rules, and DNS routes. Restart `cloudflared` after editing `config.yml`.
- For browser CORS failures, check the backend allowlist; for blocked development assets or HMR, check frontend `ALLOWED_DEV_ORIGINS`.
- If only Telegram shows stale content, follow the [frontend troubleshooting guide](https://github.com/gigstogether/gigs-together-front/blob/main/README.md#telegram-mini-app-behaves-strangely).
